## Fork

Checked 2026-11-15 for threads ([spikes](../archive/background-tasks-plan-2026-11-15.md#spikes)). OpenCode 1.19.5 (the installed `opencode acp`, model `opencode/big-pickle`; the registry's 2.3.0 was not on the computer and not tried) advertises `sessionCapabilities.fork: {}`, which the host reads (`host/crates/agent/src/acp/capabilities.rs`). `session/fork` from a second process, right after the first one's turn and while it still held the session, returned a new session that knew the chat; the original never saw what the fork was told after. The fork replays the chat's history as `session/update` before it answers (the host drops it, `drop_replay`). Cache: not shown. The fork's first turn read 1,792 of 82,200 input tokens from the cache, but so did the original's own second turn (1,792 of 82,381), while the fork's second read 82,176: on this free model the cache isn't hit reliably with or without a fork.
