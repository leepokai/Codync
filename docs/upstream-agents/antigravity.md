|---|---|---|---|
| Signed out, it starts its browser sign-in as soon as a session opens, so a usage reading would open a browser at every poll | `host/src/usage/acp_read.rs`: started with `BROWSER=true`, which its Python honors. | On Windows its server (`agy_acp_server.exe`, a `PyInstaller` onefile) ignores its closed stdin (still running 15 s later), and ended together with its launcher it leaves the launcher's ~131 MB `_MEI*` folder in `%TEMP%`. Every stop did, about every five minutes with the usage reading ([#399](https://github.com/leepokai/Codync/issues/399)) | `host/src/agent/process.rs`: once the grace period is over, a stop ends the tree from its leaves up and gives a process whose children have ended 3 s to finish (`PARENT_GRACE`), so the launcher removes its folder. Not covered: a forced stop still leaves it (the Windows service stop's `taskkill /F /T`, which app updates and **Restart host** run, signing out, a host crash), and nothing removes folders left before; the manual says how (`web/content/docs/agents.mdx`) | No issue opened yet: needs a report from someone who can reproduce it on Windows | It exits on its closed stdin. The unwinding stays: it is how every tree stops |
| Out of quota, `session/prompt` streams `"Usage Limit Reached\n\nYou have reached your current quota for this period. Your limit will reset in …"` as an `agent_message_chunk` and resolves with `stopReason: "refusal"` instead of a JSON-RPC error, so the turn ended with `"The agent declined to continue."` instead of moving on to the next login profile or fallback | `host/src/agent/fallback/reason.rs`, `host/src/agent/fallback/rest.rs`, `host/src/agent/bot/mod.rs`: `usage_limit_refusal` turns a refusal whose streamed message matches `QUOTA_REFUSAL_BANNERS` (`is_quota_refusal_banner`) into a `usage_limit_exceeded` error, and `parse_reset_in` reads the `"reset in X days, Y hours"` duration so the exhausted login rests until its quota resets | No issue opened yet: `antigravity-acp` is distributed as a closed binary in the registry | `session/prompt` returns a JSON-RPC error with `errorKind: "usage_limit_exceeded"` when quota is exhausted |

## Fork

Checked 2026-11-15 for background tasks ([spikes](../archive/background-tasks-plan-2026-11-15.md#spikes)). `initialize` advertises no `sessionCapabilities.fork` (antigravity-acp 1.4.3, the build on this computer; the registry has 1.5.0; it has `list`, `resume`). `session/fork` answers an empty result (`{}`, no `sessionId`) rather than an error, so the capability is the only thing to go by, so a background task starts from a brief. Not a defect: the capability is optional.
