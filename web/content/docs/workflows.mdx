A workflow runs a series of steps on your computer. A trigger starts it, prompts and assistants do the work, a condition picks a branch, an approval waits for you, and an output sends the result to a chat or as a notification.

A workflow belongs to the computer, not to one bot. One run can call more than one of that computer's bots. A [routine](/docs/routines) is different: it is one bot's own instruction.

## Open workflows

- **Desktop:** choose **Workflows** in the bar of icons at the left of the window, or the branch icon next to Extensions on a computer's row. The list beside the canvas shows every computer, each with its workflows under its name; a workflow being run has a mark. Click one to open it. **+** at the top starts a new workflow; with more than one computer it first asks which one. Click a computer's name to fold its workflows away or show them again. The search button finds a workflow by name or computer, and the filter button chooses which computers the list shows. The workflow's name at the top of the canvas opens its versions, rename, copy, pin and delete. A workflow opens with the hand tool, so dragging moves around the canvas; press V or choose the arrow to select and move steps.
- **iPhone and Android:** open the Workflows tab. Its title names the computer shown; with more than one computer, the filter button at the top right shows another computer's workflows. The search button beside it finds a workflow by name. On iPhone, the workflow icon next to Extensions on a computer's heading in the bot list opens them too. On the phone you look at workflows and answer their approvals: tap one to see its steps, its triggers and its run history, and tap a run to follow it. Creating, editing, running, pausing, renaming and deleting a workflow happen on the desktop or in the terminal UI.
- **Terminal UI:** open the workflow list from the computer screen. The help page names the key.

The icon is hidden when that computer is offline, or when it is running a Codync that does not have workflows yet.

## The canvas and the list

On the desktop the workflow is a canvas. Add a trigger first, then connect prompts, assistants, a condition, an approval and an output. With the arrow tool (V), drag to move a step. The bottom bar selects, pans, draws, and adds a note, a shape or text. To get the bottom bars out of the way, click the down arrow at the end of the zoom bar; the button left in their place brings them back.

In the terminal UI the same workflow is a vertical list of steps when it is a single chain, or a chain with one condition. You can add, remove and reorder those steps. A loop, a second condition, or a layout the list cannot show stays as it is: you can still change each step's settings, and the lines are kept.

On iPhone and Android a workflow shows as its steps in order, read only, with **Mode** choosing how much of each step to show.

A workflow is also a script. On the desktop, the script button opens it. A script the canvas can draw stays a graph. A script that decides its steps while it runs keeps its trigger on the canvas, and the steps show up on the run. Saving the script changes the next run. If it was saved somewhere else, the message is "This workflow was edited somewhere else".

## Build it by talking

On the desktop, a chat sits beside the canvas (the button at the top right of the window hides and shows it). Say what the workflow should do, for example "every weekday at 9, have Reviewer summarize new issues and notify me". It starts with no bot, running an agent on its own; pick a bot in the box to talk to that bot instead. Add files and pictures with **+**, as in a chat. It reads this workflow, changes it, and asks before each save; the canvas shows the change as soon as you allow it. Each save is a version, so you can go back. It works in a folder Codync keeps for the workflow unless you pick another. **New chat** begins another conversation, and **Previous chats** goes back to an earlier one.

## Run

On the desktop, choose Run to start the whole workflow, or run one trigger or one assistant from its card. A workflow only runs one at a time. While one is going, the button stops it.

Pause keeps schedules and webhooks from starting a new run. You can still run it yourself. Pausing does not stop the run that is already going.

An assistant step shows up in that bot's chat as its own turn. An approval waits until you accept or reject it. Rejecting stops the run. On iPhone and Android, open the run (a notification for it opens it too) and tap **Approve** or **Reject** on the step; that is the one thing a phone does in a run. A step you ran on its own from the desktop has no run: its notification opens the step by itself, with the same two buttons. On the desktop, clicking a workflow's system notification opens that workflow. An output either posts into a bot's chat or sends you a notification.

## Webhooks and schedules

A trigger can be manual, a schedule, or a webhook. The schedule uses the same time and time zone fields as a routine. A webhook has a URL and a secret. The secret is hidden until you reveal it. Rotating it asks you to confirm, and the previous secret stops working.

Someone calling the webhook while a run is already going gets a busy response and can try again later. A paused workflow refuses the call.

## Versions

Each workflow keeps older copies of the graph. On the desktop you can open one and restore it. Restoring keeps the graph you had as a version too. If the workflow was saved somewhere else while you were editing, your next save is refused and the editor loads the saved graph. The message is "This workflow was edited somewhere else".

## Pin a workflow

On the phone, long-press a workflow to pin it on that computer's bot list, above the bots. Pins stay on that device. The list keeps up to twenty.
