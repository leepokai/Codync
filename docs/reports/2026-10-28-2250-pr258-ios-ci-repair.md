# PR #258 iOS CI repair

## Evidence

The failing iOS Kit job was `123245531139`, workflow run `40812393130`, PR head `01a36662`. Its result bundle marked 85 tests as crashed after the test process aborted. The exported crash report identifies this stack:

`audioHeardBeforeAStopIsDropped → Dictation.stop → AVAudioEngine.inputNode → AURemoteIO::Initialize → _ReportRPCTimeout → SIGABRT`

The test injected a fake microphone opener, but stopping dictation still touched the real audio input node. That access initialized the simulator audio service, which timed out and aborted the shared test process. The same cleanup code exists on the base branch; the new Live tests were collateral failures in that process.

## Fix

Inject microphone cleanup alongside microphone startup in DictationService. The live implementation retains the original remove-tap, stop-engine and deactivate-session sequence. Tests use paired fake open/close operations. A regression test checks stop before startup, repeated stop, and restart followed by finish.

This is specific to the Apple audio test seam. Android already owns start/stop on its injected MicSource, and desktop has a separate audio implementation. No user-facing flow, release version or phone notes needed changing.

## Validation

The full iOS Kit suite ran on the dedicated iPhone simulator without automatic test retries: **311 passed, zero failed or skipped**. The simulator run directly exercised the previously crashing start/stop test. `git diff --check` passed. Three read-only after-change reviews cover correctness, completeness and structure.

Physical microphone speech was not repeated for this test-isolation fix. The live cleanup implementation is unchanged. The prior GPT-Live provider-acceptance check remains separately pending Keychain authorization; it is not represented as passed by this CI fix.

The branch was rebased onto current dev (`cd820654`) without conflicts. CI verification after push is tracked on the PR.
