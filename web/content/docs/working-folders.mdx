A bot lives in its own folder, where Codync uses Git to keep a version before and after each turn. Its threads work in your projects, where Git decides whether several of them can stay out of each other's way. This page says where each one works, what Codync leaves behind, and what to do when a folder isn't a Git repository or Git isn't installed.

## A bot's folders

Every bot has two kinds of folder, under **Workspace** in the bot's **Settings**:

- **Its own folder** (**Bot's folder**): a folder Codync makes for the bot, inside `~/.codync/bots/`. Its chat, routine runs, group chats and calls work there, and its own files stay there.
- **Its projects** (**Projects**): folders of yours, such as a project's Git repository. Threads work in the first, the default, unless the bot or you pick another.

How to add, order and remove projects is in [Workspace: its own folder and its projects](/docs/bots#workspace-its-own-folder-and-its-projects).

## Versions of a bot's own folder

When Git is installed, a bot's own folder is a Git repository that Codync keeps for it:

- **Before each turn** that works there, Codync saves the folder as it is, named `Before:` and the first line of what the bot was asked.
- **After the turn**, it saves what the turn did, under that first line.
- Nothing is saved when nothing changed. A file over 50 MB stays out of the versions, and so do the files you send the bot (its `uploads` folder). So do folders that tools fill again by themselves, such as `node_modules` and build output: they are listed in the folder's `.gitignore`, where you can add your own. A file Git can't read (locked by another program, not readable, or with a name Windows reserves such as `nul`) stays out too, until it can be read.

The bot knows this. Ask it what a turn changed, or to bring back a file as it was before, and it looks through the versions with Git.
The versions stay on your computer. A project folder never gets them: its history is yours. Neither does an own folder that was already a Git repository (one you or the bot made in it before).

Threads that work in the bot's own folder (a bot without projects, a routine without a folder, another bot's request) work there side by side, so two of them can change the same file. When one overwrites another's work, ask the bot to bring it back from a version.

## Where threads work in a project

A thread is where the bot does tasks away from the chat, with a session of its own.

| Thread | Where it works |
| --- | --- |
| One the bot starts for its own work | The folder it names, else its default project, else its own folder |
| One you start | The folder you pick, else the default project, else the bot's own folder |
| A routine's run | The routine's **Folder**, else the bot's own folder |
| Another bot's request | The bot's own folder |
| One that follows another | Where that one worked |

In a project in a Git repository, **Worktree mode** decides whether a thread gets its own copy:

- **Off:** every thread works in the project itself.
- **Side by side** (the default): the first thread works in the project itself. Each further one that starts while another thread is still working in the same repository gets its own copy.
- **Always:** every thread gets its own copy, the first one included, so none of them touches your folder.

The copy is a Git worktree: a separate checkout under `~/.codync/worktrees`, on a new branch named `codync/` and its task's title (for example `codync/fix-login`), started from the commit your folder is on. The threads never overwrite each other, and none of them touches your folder. Routine runs and other bots' requests never get one, and neither do threads in the bot's own folder.

A copy holds what is committed. Changes in your folder that aren't committed aren't in it, and neither is what Git ignores there, such as installed packages.

**Worktree mode** is under **Workspace** in the bot's **Settings**. It shows only once one of the bot's projects is in a Git repository.

## What happens to the copies

When a thread ends, Codync looks at its copy:

- **Nothing changed:** no changed or new files and no commits. The copy is removed, with its branch.
- **Something changed:** the copy and its branch stay, and the bot tells you the branch and where the copy is.
- **You merged it since:** each time Codync starts on the computer (after an update, say), it looks at the copies it kept. One with no uncommitted changes whose commits are in your folder's branch is removed, with its branch.

Codync never merges, rebases or deletes a branch that has work on it. Bringing the work in is yours to do, or the bot's when you ask it.

### Bring the work in yourself

In your own folder, merge the branch, then remove the copy and the branch:

```sh
cd ~/projects/my-app
git merge codync/fix-login
git worktree list                       # shows where each copy is
git worktree remove ~/.codync/worktrees/…/…
git branch -d codync/fix-login
```

`git merge` brings in commits only. If the thread left changes it didn't commit, commit them in the copy first. Git refuses to remove a copy that still has uncommitted changes, and `git branch -d` refuses a branch that isn't merged, so nothing is lost by accident.

## Without git

Codync can keep versions and give threads their own copies only with Git. In both cases below, every thread of the bot in that folder writes in it, and two that work at the same time can overwrite each other's files.

### The folder isn't a Git repository

A project may not be a Git repository. (A bot's own folder becomes one by itself once Git is installed.) Choose one of these:

- **Keep to one at a time.** Set **Threads at once**, under **Workspace** in the bot's **Settings**, to 1. Further tasks wait their turn, except while a thread waits for you (an approval, a choice or a sign-in): then the next task starts in the same folder, and once you answer, both work there at once. To keep them apart even then, make the folder a repository. The number limits only the bot's own tasks: a thread you start yourself runs at once, beside them in the same folder, so to keep your own threads apart too, make the folder a repository.
- **Make the folder a repository.** A copy starts from a commit, so the folder needs at least one:

```sh
cd ~/projects/my-folder
git init
git add -A
git commit -m "First commit"
```

Be careful with that first commit: `git add -A` takes every file in the folder. List what should stay out (passwords, keys, large files, installed packages) in a `.gitignore` file before you run it.

### Git isn't installed

Without Git on the computer the bot runs on, a repository gives no copies either: threads work as in a folder that isn't one. Install Git there:

| Computer | Command |
| --- | --- |
| macOS | `xcode-select --install`, or `brew install git` with Homebrew |
| Debian, Ubuntu | `sudo apt install git` |
| Fedora | `sudo dnf install git` |
| Windows | `winget install Git.Git`, or the installer from git-scm.com |

Then restart Codync on that computer, so it finds Git.

## Where the apps show it

- **Under each task that is or was worked on**, in the bot's **Details** and in **Threads**, a line says where its thread works: the folder when it works in a folder itself, the branch when it has a copy of its own. Your home folder is written as `~`. On the desktop, hold the pointer over the line to see the full path.
- **At the top of a thread** (tap or click its task's row), the same line is a button: tap or click it to copy the full path. It reads **Path copied** for a moment.
- **Settings > Workspace > Projects** marks each project: a branch icon for one in a Git repository, a folder icon for one that isn't.
- **Terminal UI:** a task's row has no such line; the heading of its thread's steps shows its branch or folder, and doesn't copy.
